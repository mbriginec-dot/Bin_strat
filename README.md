# Crypto Signal Bot — фінальна версія (v5, Bybit)

Бот для внутрішньоденної торгівлі на **Bybit** (топ-60 активів за сумарним обсягом
USDT+USDC+USD), побудований на методології цінових рівнів з книги Андрія Герчика
"Курс активного трейдера". Шле два типи повідомлень у Telegram:

- 🔎 **Радар** (0.5% від рівня) — чисто інформаційне: рівень, денний контекст (ATR,
  обсяг, зміна ціни), щоб ти встиг підготуватись і слідкувати за графіком самостійно
- ✅ **Підтверджений сигнал** — коли патерн (пробій/відбій/хибний пробій) підтвердився
  на 5-хвилинці: точка входу, стоп, тейк + **повний чекліст 8 підтверджень з книги**

⚠️ **Бот нічого не торгує сам.** Тільки сповіщення. Рішення про вхід і сам ордер —
завжди твої, вручну на біржі.

> **Чому Bybit, а не Binance?** Binance.com блокує запити з дата-центрів GitHub
> Actions (HTTP 451, обмеження за геолокацією сервера — не за твоїм місцем
> знаходження). Bybit такого блокування не має, тому бот працює стабільно
> незалежно від того, де фізично перебуваєш ти.

## Логіка роботи (як усе поєднано)

**1. Рівні — з кількох таймфреймів:**
- **1D** — основні, завжди враховуються
- **4h / 2h / 1h** — тільки якщо рівень "сильний" за формулою книги, з **підвищеним
  порогом** сили (молодші ТФ дають більше шумових дотиків, тож поріг вищий)

**2. Точка входу — на 5-хвилинному графіку**, максимально близько до рівня.

**3. Стоп-лосс = рівень ± ATR(5хв)**, розрахований **за точною методикою з книги**:
середнє (high−low) за 3-5 останніх завершених барів, з ВИКЛЮЧЕННЯМ "паранормальних"
барів (≥2×ATR або ≤1/3×ATR) — вони замінюються сусідніми нормальними.

**4. Радар — суто інформаційний**, без точки входу/стопу/тейку. Дає контекст:
зміну ціни за день, обсяг за день, % пройденого денного ATR, середній денний ATR.
Повторний радар по тому самому рівню шлеться лише після ретесту (ціна відійшла і
повернулась).

**5. Підтверджений сигнал — з повним чеклістом.** Коли патерн підтверджується на
5хв, бот рахує точку входу (поточна ціна), стоп, тейк (3:1) і перевіряє **8 факторів
з книги**:

1. Сила рівня (дотики / хибні пробої / кругле число, з урахуванням ТФ)
2. Імпульс (рух ≥2-3x ATR(5хв) — розділ книги про підтвердження руху)
3. Обсяг (підтверджує рух чи ні)
4. Тренд на 1D (сигнал за трендом чи проти)
5. Запас денного ATR (не пройдено 75-80%; виняток — новий локальний екстремум)
6. Технічний ATR (найближчий інший рівень не "затискає" простір для руху)
7. Запас ходу до протилежного рівня (мінімум 4 стопи — розділ книги "чому потрібно
   мінімум чотири стопи")
8. Підтвердження зі старшого/іншого таймфрейму (той самий рівень сильний і там)

Поріг для надсилання наразі **не застосовується** — сигнал шлеться завжди, коли
патерн підтвердився, а чекліст (X/8) інформує про якість сетапу. Це можна змінити
пізніше в `main.py`, якщо захочеш фільтрувати за мінімальною кількістю підтверджень.

## Крок 1. Створи Telegram-бота

1. **@BotFather** → `/newbot` → отримаєш **TELEGRAM_BOT_TOKEN**.
2. Напиши своєму боту будь-яке повідомлення.
3. **@userinfobot** → дізнаєшся свій **chat_id**.

## Крок 2. GitHub-репозиторій

1. Зареєструйся на https://github.com.
2. Створи приватний репозиторій, завантаж туди всі файли цього проекту.

## Крок 3. Секрети в GitHub

**Settings → Secrets and variables → Actions**:
- `TELEGRAM_BOT_TOKEN`
- `TELEGRAM_CHAT_ID`

## Крок 4. Онови список пар (топ-60)

`pairs.json` вже містить орієнтовний список 60 пар. Для точного актуального
топ-60 за сумарним обсягом:

```bash
pip install -r requirements.txt
python update_pairs.py
```

## Крок 5. Увімкни GitHub Actions

**Actions** → підтверди увімкнення → workflow **"Crypto Signal Scan"** вже
налаштований на автозапуск кожні 15 хв. Для перевірки одразу — **Run workflow** вручну.

## Крок 6. Перевір результат

Дивись Telegram і вкладку **Actions** (чи запуск пройшов без помилок).

## Структура проекту

```
crypto-signal-bot-v4/
├── main.py                    # головний скрипт — оркестрація всього циклу
├── config.py                  # усі налаштування (ТФ, пороги сили, ATR, чекліст)
├── pairs.json                 # список пар (топ-60) — редагуй вручну
├── update_pairs.py            # перегенерувати топ-60 за сумарним обсягом
├── data_fetcher.py            # отримання свічок з ccxt-біржі
├── levels.py                  # пошук/оцінка сили рівнів + пошук найближчого/протилежного
├── multi_tf_levels.py         # збір рівнів з кількох ТФ (1D + 4h/2h/1h якщо сильні)
├── book_atr.py                # ATR за методикою книги (виключення паранормальних барів)
├── indicators.py              # RSI, обсяг, тренд, імпульс, % ATR, локальний екстремум
├── strategy.py                # 3 патерни + розрахунок стопу/тейку
├── checklist.py               # збірка чекліста з 8 підтверджень для сигналу
├── state.py                   # пам'ять бота (state.json), ключі з урахуванням біржі
├── telegram_notifier.py       # формат повідомлень (радар / сигнал+чекліст)
├── .github/workflows/scan.yml # розклад автозапуску
└── requirements.txt
```

## Що можна налаштувати в `config.py`

- `MIN_LEVEL_STRENGTH` — пороги сили окремо для кожного ТФ (`{"1d": 3, "4h": 5, ...}`)
- `ATR_LOOKBACK_BARS`, `PARANORMAL_MAX_MULTIPLIER`, `PARANORMAL_MIN_FRACTION` — методика ATR
- `DAILY_ATR_CONSUMED_WARNING_PCT` — поріг "запасу ходу" (за книгою 75-80)
- `MIN_STOPS_IN_ROOM_TO_OPPOSITE_LEVEL` — мінімум стопів у запасі ходу (за книгою 4)
- `RADAR_DISTANCE_PCT` — дистанція радару (0.5%)
- `IMPULSE_ATR_MULTIPLIER` — поріг імпульсу (2-3x за книгою)
- `TOP_N_PAIRS` — кількість пар для сканування (зараз 60)

## Відомі обмеження цієї версії (MVP)

- Рівні перераховуються з нуля щоразу; ідентифікація рівня між запусками — за
  округленою ціною.
- "Технічний ATR" рахується як відстань до найближчого ІНШОГО знайденого рівня —
  спрощення методики книги (там це ширше поняття технічних перешкод).
- % пройденого денного ATR рахується від ціни відкриття поточного дня, отриманої
  з останнього (ще не закритого) денного бару — залежить від того, як біржа формує
  цей бар у реальному часі.
- Немає бек-тестингу — точність ще не перевірена на історії, дивись на результати
  перших сигналів критично і адаптуй пороги.
- Поріг для фільтрації сигналів за кількістю підтверджень (X/8) поки не застосовується
  — усі підтверджені патерни шлються, чекліст лише інформує.

Природні наступні кроки після накопичення практики використання.
